# 自动化与代理边界

## 代理说明

| 项目 | 当前实现 |
| --- | --- |
| 触发 | 使用者显式调用 `/manmantalk`（或直接说出育儿沟通问题），或宿主根据 Skill 描述匹配相关请求 |
| 所有者 | 使用者控制当前任务；维护者维护公开指令 |
| 自动运行 | 只在当前任务内响应，不存在后台或定时运行 |
| 可读输入 | 当前对话、按需 Markdown、已同意的受限记忆、使用者提供的录音与记录 |
| 必需工具 | 无。转写默认用本地脚本（需 `faster-whisper`），不可用时降级为接受文本逐字稿；本地记忆与云端转写都可选 |
| 外部副作用 | 默认无网络副作用。**使用者自行配置腾讯云密钥后**，转写会把音频上传到腾讯云，并产生按量计费——这是使用者自己的选择 |
| 审批 | 是否启用记忆、是否启用云端转写、是否上传记录、是否采用建议，均由使用者自行决定 |

## 提示词引导与硬边界

`SKILL.md` 包含首次建档、角色确认、主题路由、轮次上限与收束、五步分析、输出格式和安全边界。这些属于**模型引导，并非程序级强制控制**。

真正的硬边界来自两处：

1. **宿主环境**：模型安全政策、文件系统权限、网络权限、工具参数校验和用户批准。
2. **本地脚本**：`scripts/memory_store.py` 的同意门禁、字段白名单／黑名单、条数与长度上限是**代码级强制**；`scripts/transcribe.py` 的路径选择（没密钥就不走云端）、5MB 限额校验和转写中间文件清理同样是代码级——**不靠提示词自觉**。

仓库不能声称仅靠提示词彻底阻止越权或有害输出；能强制的地方在脚本，其余靠宿主。

## 输出契约

常规回答应尽量包含：

1. **照见**：谁说了什么、在哪一句转折（有原话时给位置）。
2. **事实拆分**：原话能证明的、使用者转述的、合理推测的、仍然未知的。
3. **两边证据**：做得不好的地方、做得好的地方，分别给证据。
4. **判断与说法**：有逐字材料（录音转写、截图原文）时给总评等级与维度分，只有口述和回忆时用描述性判断、不给分数；加一句首选和 2–3 条可直接照说的句子。
5. **反应预案**：孩子可能有哪几种反应，分别怎么接。
6. **本轮落点**：一件现在能做的小动作、观察窗口或停止条件。到收束轮时整段换成六段式整体说明，并明确宣布不再提问。

若使用者只要一句话，第一屏先给成品，不先展开分析。报告末尾固定一行：**这不是诊断，也不替代专业帮助。**

## 表达纪律（硬性）

- 每一次的说法都要**从这一次的真实对话里长出来**，贴合长辈平时的用词，只对眼前这一件事负责。
- 不说「你应该多共情」这类空话；给能执行的句子。
- 不给通用话术库，不给万能回复。
- **禁止**：撤回关注、制造愧疚、反话施压、装可怜、拿别人家孩子比较、威胁不再爱、给孩子贴标签。
- 把猜测改成「我看到……是不是……」；猜错时直接承认。
- 转写给的是物理量（时间、文字、音量、语速）和声学聚类编号，**不把它们翻译成心理状态**。「语速快」不等于焦虑，「音量低」不等于压抑；字段缺了就如实说缺，不补、不圆。

## 失败处理

- **资料缺失**：标注未知，不虚构；不为了完整而编内容。
- **资料矛盾**：指出矛盾并请求纠正关键项。
- **角色未确认**：明确说明「角色为推测，可能有误」，或建议重录，不装作知道。**云端路径被切片时，还要说明跨片编号不可比。**
- **工具不可用**：继续提供纯文本分析，不假装已执行转写或已保存记忆，**也不伪造转写结果**。
- **云端不可用**：密钥没配、网络不通、签名失败或额度用尽时，**如实说明失败原因，并提示可以改用 `--provider local` 在本机跑**；不静默改用本地后假装走的是云端，也不谎称已上传。
- **记忆写入失败**：明确说明没有持久化，不显示「记忆更新」成功提示。
- **高风险情形**：暂停常规报告，先给渠道，再问使用者是否仍要看分析。
- **法律或医疗不确定**：说明局限，建议核对地区和咨询合格专业人员。
