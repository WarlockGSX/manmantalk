# 架构说明

## 产品概览

慢慢Talk 是一个本地 Skill，由行为指令、界面元数据、按需加载的 Markdown 知识库、转写脚本、可选的本地记忆脚本和一张参考图组成。仓库不包含服务器、前端应用、账号系统或遥测；用户明确同意后，记忆脚本在操作系统用户数据目录创建有界 SQLite 文件，绝不写入仓库。语音转写**默认**在本机离线完成，不需要账号或密钥；使用者自行配置腾讯云密钥后，转写脚本会自动改走云端（可给说话人编号），此时录音会上传。云端不是默认路径，包内也不携带任何凭据。

## 运行方式

Agent 根据 Skill 描述决定是否加载 `SKILL.md`。被调用后，先判断这次拿到的是什么（录音／逐字稿／只有转述）：拿到录音时先用 `scripts/transcribe.py` 转成结构化逐字稿（脚本按环境变量决定走本地还是云端，`--provider` 可覆盖），有原话时先做**说话人角色确认**，再按本次主题读取 1–3 份参考。最终输出是照见、事实拆分、判断与可直接照说的说法，以及观察窗口或停止条件；Skill 不自动向任何第三方发送消息，也不读取聊天软件数据库。

`SKILL.md` 只保留核心流程、路由和安全边界，默认按问题读取 1–3 份参考。**运行时同步白名单**是 `SKILL.md`、`references/`、`scripts/` 以及存在时的 `assets/`；`documentation/` 与 `examples/` **随包分发但不进安装副本**——它们给维护者和上架审核者看，装到别人机器上不会有，也不影响使用。

**定稿后的包内不含任何过程文件。** 早期开发期的草稿（`draft/`：原文对照、结构设计、骨架、待确认清单、助手备注、references 早期快照）已在定稿后移出本包，归档在包外的 `_archive/` 下（早期快照保留当时的旧名目录），仅供回查，不参与运行，也不随包分发。安装副本不携带 `documentation/` 也能正常工作。

**发行与提交材料同样移出包外。** 上架材料包（`README-SUBMIT.md`：frontmatter 字段表、介绍文案、封面与截图说明、安全声明、审核问答口径、提交清单）与 GitHub 上架指南（`GITHUB-上架指南.md`）属于**发布流程文档**，不是技能本体，已移出本包，存放于包外的工作目录；包内不再保留，打包时也不再包含。

## 两层参考的划分

`references/` 内部严格分为两层，加载顺序是「先读机制、再读做法」：

| 层 | 目录 | 回答的问题 | 谁先读 |
| --- | --- | --- | --- |
| 机制层 | `references/knowledge/` | 为什么会这样、怎么判断、边界在哪 | 先读（按主题路由） |
| 做法层 | `references/practical/` | 这一步该怎么做、这句话怎么说 | 要动手时再读 |

两份特殊文件不在常规路由的主路径上：

- `references/knowledge/08-危机识别与求助渠道.md`：**只在出现危机信号时读**，用途只有一个——决定怎么把求助渠道给出去。它不参与报告里的判断。
- `references/practical/10-长期记忆与亲子档案.md`：**只在需要跨任务档案时读**，用于检查同意状态与字段规范。

## 信任边界

1. **使用者 → Agent**：使用者可能提供高度敏感的亲子冲突、孩子的心理与身体状况、家庭变故与法律纠纷信息。
2. **Skill 指令 → 模型推理**：`SKILL.md` 是行为引导，不是不可绕过的程序级强制器。
3. **参考文档 → 模型上下文**：知识文件可能过时或存在错误，不能视为实时法律、医疗或危机数据库。
4. **模型建议 → 现实行动**：使用者决定是否采用这些说法或采取行动；Skill 不自动执行这些副作用。
5. **Agent → 本地记忆**：只有首次明确同意后才能写入；脚本执行字段白名单、黑名单、条数上限和撤销校验，数据库权限依赖操作系统用户目录。
6. **录音 → 转写文本**：默认在本机完成，不上传。使用者自行配置腾讯云密钥后，脚本会**自动**改走云端，**录音会上传到腾讯云处理**——这是使用者自己的选择，包内不含凭据，也不会替别人启用。**云端给的是说话人编号，不是角色**；本地路径不产生该字段，云端路径若因超过 5MB 被切片，编号还只在片内可比。两种情况都必须经使用者确认后才升级为事实，切片时还要额外确认跨片对应关系。
7. **参考依据 → 正文落点**：每份 `## 参考文献` 里的条目都必须在正文有对应角标；引入不匹配的依据会造成「链接与依据不匹配」，属明令禁止。

## 云端转写的实现约束与验证记录

腾讯云路径不能用 SDK（会引入依赖），因此 `scripts/transcribe.py` 用标准库自己实现 TC3-HMAC-SHA256 签名。签名是最容易写错、且错了只报 `SignatureFailure` 看不出原因的地方，所以按下面的方式验证过：

**约束（对照官方 Python SDK 源码 `tencentcloud/common/abstract_client.py` 核出）：**

1. 参与签名的请求头**只有 `content-type` 和 `host`**，不含 `x-tc-action`。
2. `Content-Type` 取 `application/json`，**不带 charset**。
3. 请求体用默认 `json.dumps`（`ensure_ascii=True`），body 全 ASCII，避免无 charset 时的编码歧义。
4. `Credential` 的日期取 `X-TC-Timestamp` 换算的 **UTC+0** 日期；用本地时区会「白天能调通、凌晨必失败」。

**验证方式：** 装入官方 `tencentcloud-sdk-python-common`，用它的 `Sign.sign_tc3` 加 SDK 自己的规范请求串拼法重建参考实现，与 `tc3_authorization()` 的输出**逐字节比对**。

| 验证项 | 结果 |
| --- | --- |
| CreateRecTask 路径 × 4 个不同时间戳（跨不同日期） | 4/4 Authorization 字符串完全一致 |
| DescribeTaskStatus 路径（不同 payload） | 一致 |

**尚未验证的部分（诚实记录）：** 真实调用未跑过——没有可用密钥。因此以下依赖首次实跑确认：接口对 opus（`ogg-opus`）容器的接受程度、`ResultDetail` 字段名的实际大小写（代码已对大小写不敏感）、以及错误码分支。脚本为此提供 `--dump-raw`，会把每次调用的原始响应落盘，便于首次实跑时立刻核对。

## 已知风险与假设

- 宿主没有本地文件权限或脚本不可用时，档案只能在当前任务中使用；Agent 必须诚实说明没有持久化，不得声称「已记住」。
- SQLite 可提供事务与条数上限，但不能替代磁盘加密、操作系统账号隔离或宿主安全控制。
- **未成年人保护是最高优先级风险面**：任何形式的打分、测评、贴标签、诊断都被明确排除；孩子的反应只作为「家长做法是否起了作用」的观察记录。
- 模型可能把推测写得过于肯定，必须依赖「事实／推测／未知」拆分降低风险。
- 法律条文与社会渠道具有时效性，引用前需要复核日期与地区。
- 学段与青春期状态是粗档，用于校准判断口径，不能替代对具体孩子的观察，也不能据此推断个体发育水平。
- 提示词安全边界不是程序级安全控制；高风险使用仍依赖宿主模型政策。

## 不适用的系统文档

- 无邮件发送，因此无 `emails.md`。
- 无定时或后台任务，因此无 `cron.md`。
- 无公开 Web 路由或 SEO 表面，因此无 `seo.md`。
- 包内不含任何 API 密钥、OAuth 或客户端秘密。**唯一涉及的凭据是使用者自己提供的腾讯云密钥**，只从环境变量读取，不入库、不进仓库、不写日志（见 [变量与配置](variables.md)）。
